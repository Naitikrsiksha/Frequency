Microphone access

Frequency Analyzer listens to surrounding sound through your device microphone and analyses it live with the Web Audio API (FFT).

  • Your browser will ask for microphone permission when you press Start.
  • Audio is processed locally in your browser. It is never recorded, stored or uploaded.
  • Only numbers (levels, frequencies) are kept, and saved on this device only if you enable “Save numeric history”.
  • Readings are uncalibrated estimates. A phone is not a professional sound-level meter.

Optional SPL calibration not calibrated

To turn dBFS into an approximate dB SPL, compare against a reference meter.

  1. Start the analysis and place the phone next to a reference sound-level meter.
  2. Play a steady noise (e.g. pink noise) at a moderate level (about 60–85 dB).
  3. Type the reference reading below and press Calibrate now.

Offset = reference − measured dBFS (1 s energy average). Valid only for this device, browser and microphone setup, and not frequency-weighted (most meters show dBA). Expect errors of several dB; accuracy is poor near the microphone's noise floor and near clipping. Never treat the result as a certified measurement.

Notes & how to read this

Scientific notes
  • Frequency (Hz) is pitch-related; amplitude (dB) is level-related. Loudness and pitch are different properties.
  • A sound contains many frequencies at once. The dominant frequency is just the strongest FFT bin; the fundamental is the lowest periodic component, often weaker than a harmonic.
  • FFT resolution Δf = fs/N. Peak interpolation refines the estimate but cannot separate components closer than about Δf × 2.
  • Frequency alone cannot say whether a sound is harmful; risk depends on level, exposure duration and environment.
  • Level is the RMS of the digital signal (125 ms “fast” smoothing, unweighted). Average is an energy (Leq-style) average, not an average of dB values.
  • Noise categories only use dB SPL thresholds when you calibrate. Otherwise they are relative to this device's input level.
Run on an Android phone
  1. Easiest: host this one file on any HTTPS site (GitHub Pages, Netlify Drop, Cloudflare Pages), open the link in Chrome, press Start, tap Allow.
  2. Termux: install Termux, put index.html in a folder, run python -m http.server 8000, then open http://localhost:8000 in Chrome (localhost counts as secure).
  3. USB from a PC: run python3 -m http.server 8000 on the PC, enable USB debugging, run adb reverse tcp:8000 tcp:8000, then open http://localhost:8000 on the phone.
  4. Plain http://192.168… addresses are blocked from using the microphone. Use HTTPS or localhost.
  5. If permission was denied: Chrome ⋮ → Site settings → Microphone → allow, then reload. Keep the screen on; browsers pause analysis in the background.
